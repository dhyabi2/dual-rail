Also checked, and the reason two of the rules above exist at all - both were
found by this script and neither by hand:
  * `extra` is z.record(z.unknown()).optional().nullable(), so an entry whose
    extra is a string takes the whole accepts[] array down with it. The
    validator did not check extra's type until this run said so.
  * JSON has one number type, so `"x402Version": 1.0` IS version 1 and zod's
    z.literal(1) matches it. Python's json gives that back as a float, which
    an isinstance(value, int) check read as no version at all.

To re-run after an @x402/core release, install that version instead and
replace this file. A mismatch here is a real finding either way: the schema
moved, or the validator was wrong.
